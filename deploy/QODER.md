# Qoder 国内版渠道

## 接入范围

- 账号管理支持 Qoder 网页设备 OAuth 授权、新增账号及重新授权。
- 后台、请求时和管理员手动续期复用统一刷新 API，凭证更新校验旧凭证及代理，避免覆盖并发重新授权结果。
- 模型目录按账号动态读取；支持聊天补全、Responses 和 Messages 协议转换，以及标准函数工具调用。
- 账号列表的用量窗口显示订阅 Credits、共享池和资源包；查询失败保留最近成功结果并标记过期，首次失败显示未知。
- Qoder 仅接受 OAuth 账号，不支持以普通 API Key 接入。
- 个人中转复用相同的添加、编辑、重新授权、测试和统计组件；授权会话按用户及管理范围隔离，重新授权校验账号归属。个人分组、公共共享、综合分组路由、API 密钥、计费与收益沿用现有逻辑。
- 额度接入现有账号单项和批量用量接口，在 `qoder_credits` 字段返回订阅 Credits，不把上游 Credits 当作站内用户余额。
- 渠道监控可选择 Qoder 并关联账号查询 Credits 配额，复用现有状态、告警和历史展示。该 provider 与 Antigravity 一样只开放配额监控；账号连接测试使用原生 Qoder 转发。

## 使用

1. 在管理后台新建 Qoder 分组。标准模式使用 `/v1/messages` 时，开启分组的 Messages 调度。
2. 在账号管理添加 Qoder 账号，设置名称、分组及代理，进入授权步骤。
3. 打开官方授权页并确认，网页会自动轮询并保存授权账号；令牌不经过浏览器。
4. 查询实时可用模型，为该分组创建 API 密钥后调用统一网关。
5. 账号的重新授权和凭证刷新使用账号管理现有入口；Credits 使用账号列表现有用量入口。

调用应使用账号实际可用的 Qoder 模型名。个人模式下 Qoder 分组默认开启 Messages 调度。实时、生图、嵌入及原生压缩不在本次接入范围内。

## 本地开发

首次创建 `deploy/.env` 并配置数据库密码、固定 JWT/TOTP 密钥及可选管理员凭证，然后从仓库根目录运行：

```sh
make docker-dev
```

默认地址为 `http://127.0.0.1:8080`。修改源码后重新运行该命令构建；本配置没有源码热更新。数据保存在 `sub2api-dev` 项目的 Docker 命名卷中。
